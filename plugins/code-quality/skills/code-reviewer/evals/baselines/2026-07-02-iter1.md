# code-reviewer — baseline iter1 (2026-07-02)

First committed evidence for `blassioli:code-reviewer`. Method: each fixture reviewed
**with the skill** vs a **baseline** (plain "senior engineer, review this" prompt) on the
**same underlying model** (Opus 4.8, inherited). Author-graded against `evals/evals.json`
expectations with quoted evidence. **Single run per config** (no variance yet); grading
was by the author, not an independent grader — both are the obvious next iteration.

## Result

| Config | Discriminating cases (1–3) | Over-trigger control (4) |
|---|---|---|
| **with-skill** | **13 / 13 (100%)** | **pass** — declined and routed to `commit-hygiene` / `gh-pr-creator` |
| **baseline** | **11 / 13 (84.6%)** | (control not run for baseline) |

**Delta: +15.4pp**, and it comes entirely from **severity-vocabulary discipline** — not
detection. A strong model reviewing without the skill finds essentially the same
substantive bugs; it just doesn't grade them.

## Per-case

### 1. non-idempotent-consumer — with-skill 4/4, baseline 3/4
Both caught the core bug. With-skill (quoted): *"at-least-once push plus a 10s ack
deadline means any redelivery … re-runs the whole body and double-charges"* → **BLOCKER**;
also flagged charge-before-PAID ordering and the 10s-deadline-vs-three-external-calls race.
Baseline caught the double-charge, missing dedup, and ordering too — but graded it as
*"the big one … must not merge"* with **no BLOCKER/HIGH label** (expectation 4 miss).

### 2. api-contract-break — with-skill 4/4, baseline 3/4
Both caught the `userId→user_id` rename and the `204`-with-body contradiction and
recommended versioning. With-skill labeled both **BLOCKER**; baseline said *"Request
changes"* with **no BLOCKER label** (expectation 3 miss).

### 3. k8s-missing-probes — with-skill 5/5, baseline 5/5
Parity. Both caught missing probes, missing requests/limits, `:latest`, and graceful
shutdown, with severity. With-skill added worker-specific depth (HPA on Pub/Sub backlog,
Workload Identity SA, PDB); baseline independently raised security-context — a good
finding the suite didn't ask for.

### 4. over-trigger control — with-skill pass
*"this request is explicitly not a code review … Routing you to … `gh-pr-creator` …
`commit-hygiene`."* Correctly declined; no severity-graded report.

## Interpretation

- **The skill earns its keep on consistency, not novelty.** Its measurable value over a
  strong model is the enforced `BLOCKER/HIGH/MEDIUM/LOW/QUESTION` severity contract, the
  structured output, the archetype/lens framing, and a clean over-trigger boundary.
- **Detection parity** means the fixtures may be too "textbook." Next iteration: add
  subtler traps (a bug that only shows under partial failure / a plausible-but-wrong
  "looks fine, tests pass" steel-man) where a baseline is likelier to miss the *substance*.

## Next iteration
- Independent grading via `skill-studio` `skill-creator-grader` (remove author-grading bias).
- ≥3 runs per config for variance.
- Harder fixtures targeting detection delta, not just severity discipline.
