# Engineering Documentation

Write clear, maintainable technical documentation for the right audience and
purpose.

## Good Fits

- creating docs from scratch
- repairing unclear or outdated docs
- choosing the right structure for a README, runbook, onboarding guide, or API
  reference

## Document Types

- README: what this is, why it exists, quick start, configuration
- API docs: endpoints, request and response examples, auth, errors
- Runbook: when to use, prerequisites, procedure, rollback, escalation
- Architecture doc: context, design, trade-offs, data flow
- Onboarding guide: environment setup, key systems, common tasks

## Useful Inputs

- intended audience
- what the reader needs to do after reading
- the current source of truth, if one exists
- whether this is a new document or a rewrite

## Principles

1. Write for the reader, not the author.
2. Start with the most useful information.
3. Show with commands, examples, or diagrams when useful.
4. Keep docs current.
5. Link instead of duplicating.

## Common Mistakes

- writing for experts when the reader is new to the system
- starting with background instead of the first practical step
- duplicating fragile details that already have a better source of truth
